# Decision Log

## Decisions

### Treat TaylorDo as an open engineering project

TaylorDo is not merely a disk optimizer. It includes software, Design Science, documentation, outreach, and future research.

### Keep documentation canonical in the repository

The website should publish or adapt the repository documentation.

### Use Design Science documents

Design Science explains why TaylorDo is designed as it is.

### Separate dedication and technical acknowledgement

The project dedication to Matt Taylor remains. Jeroen Kessels is acknowledged for creating JkDefrag and MyDefrag.

### Avoid exaggerated marketing

TaylorDo should not be positioned as a generic PC speed booster.

### Treat Rust as future architecture work

A Rust implementation should follow a formalized TaylorDo model rather than immediately replacing the MyDefrag implementation.

### Treat evaluation as a separate work stream

Future evaluation should define measurements, benchmarks, and validation methods.
